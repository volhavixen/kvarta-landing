# Кварта: лендинг обжарки

Тестовое задание (веб-разработчик junior+). Основной макет выбран: `mockups/combined.html`.
Описание выбора макета и список правок: `mockups/README.md`. Альтернативы: `mockups/alternatives/`.

## Стек и хранилище заявок

Next.js (App Router, TypeScript), один маршрут `POST /api/lead`. Заявки хранятся в **Upstash Redis**, дубль уходит в Telegram-бот.

Почему Redis, а не файл или SQLite: на бесплатном Vercel файловая система только для чтения и между запросами не сохраняется, SQLite-файл там жить не будет. В Upstash защита от дублей делается одной атомарной командой `SET ключ NX EX 600`: номер занят на 10 минут, второй запрос (в том числе двойное нажатие) не создаёт заявку. Свою базу поднимать не нужно, есть бесплатный тариф. Если Telegram недоступен, заявка всё равно принята; если недоступен Redis, человек видит сбой и телефон мастерской.

Запуск: `npm i`, `.env.local` по образцу `.env.example`, `npm run dev`. Тесты: `npm test` (логика), `npm run e2e` (форма на мобильном экране).

## API: `POST /api/lead`

Тело (JSON): `name`, `phone`, `type` (`subscription` | `once` | `question`), `comment`, `source` (`page`, `referrer`, `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `gclid`, `fbclid`, `yclid`), `website` (скрытая приманка для ботов, должна быть пустой).

Ответы: `200 {ok:true}` (в том числе повтор номера: `duplicate:true`), `400 {field, message}` (неверный номер или тип), `429` (больше 10 заявок за 10 минут с одного IP), `502` (хранилище недоступно, заявка не создана).

Номер: мобильные `25/29/33/44` и минские городские `17`, ровно 9 цифр после `+375`. Городские номера других областей не принимаются намеренно (сайт для Минска); лишние цифры отклоняются, а не обрезаются.

Источник заявки: рекламные метки и реферер запоминаются в рамках сессии. Если первый заход был без меток, а потом человек пришёл с рекламы, сохраняется рекламный заход.

Дубли: номер и заявка записываются в Redis одним атомарным скриптом, поэтому нет состояния «номер занят, а заявки нет».

Менеджер узнаёт о заявке из Telegram. Если `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` не заданы, уведомления не уходят (в логе предупреждение), а заявки лежат только в Redis, список `leads` (смотреть в консоли Upstash). В рабочей версии задайте обе переменные.

## Что делали сами, а что ИИ

Сами: выбор макета и его правки (см. `mockups/README.md`), требования и допущения, решение по хранилищу, проверка результата в браузере.
ИИ (Claude Code): план по брифу, вся логика с тестами по шагам (телефон, дата обжарки, калькулятор, API), перенос макета в компоненты, e2e-тесты, замер Lighthouse.

## Где ИИ ошибся и как это заметили

- Бриф-PDF ИИ сначала не смог прочитать (нет текстового слоя) и составил план по краткой выжимке. Заметили сразу, поставили `poppler`, перечитали все 4 страницы и дополнили план (README, пакет к отправке).
- В плане был тест с неверным ожиданием: для среды ближайший четверг «завтра», а не «в четверг». Тест упал до реализации, стало ясно, что ошибка в ожидании, а не в коде; тест исправлен.
- План предлагал вынести обработчик заявки в файл маршрута, но Next.js не разрешает лишние экспорты из `route.ts`. Обработчик вынесен в `lib/handle-lead.ts`, чтобы его можно было тестировать без Redis.
- В e2e-тесте локатор телефона нашёл два элемента (форма и футер) и упал; сузили до блока сбоя.
